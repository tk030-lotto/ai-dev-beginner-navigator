# 【振り返り】AIコーディングアシスタントと規範（AGENTS.md）を守りながらWebアプリを作り切った知見

## はじめに

「AIに頼んだら、指示していないファイルまで勝手に書き換えられて動かなくなった」
「良かれと思って入れたリファクタリングで、既存のテストが壊れていた」
「気づいたら巨大なコミットが1つだけ作られていて、何が変わったか追えない」

自律型AIコーディングアシスタント（Antigravity、Claude Code、Cursor等）を使って開発を進めると、誰もが一度はこのような「AIの暴走と手戻り」に頭を抱えます。

「AI開発初心者ナビ」のプロジェクトでは、**明確な行動規範（`AGENTS.md`）**をエージェントに課し、プロトコルに従って開発を進めることで、破綻することなく全30プラグイン・テスト全件通過・セキュリティ対応まで完走させることができました。

本連載の締めくくりとして、AIアシスタントを真の「頼れるペアプロ相手」にするためのルール設計と運用ノウハウを振り返ります。

---

## AIが暴走する根本原因

AIは基本的に「ユーザーの期待に応えよう」「問題を先回りして解決しよう」とする強い動機（アラインメント）を持っています。
しかし、この親切心が開発においては裏目に出ます。

- **先走り実行**: 「次はおそらくこれが必要だろう」と勝手にファイルを新規作成する。
- **不要なリファクタリング**: バグ修正を頼んだだけなのに、関係のないコードの命名や構造まで変えてしまう。
- **検証の省略**: コードを書き換えただけで満足し、テストやビルドの成否を確認せずに「完了しました」と報告する。

これらを防ぐには、人間側の「プロンプトの工夫」だけでは限界があります。**システム的に拘束力を持つ「行動規範ルール」**を定義する必要があります。

## 開発を支えた4大プロトコル（AGENTS.md）

本プロジェクトで最も効果を発揮したルールを紹介します。

### 1. 【最厳守】事前承認の義務（第6条）
> **ユーザーからプロンプトを受け取った際、まず必ずチャット上で「これから何を行うか」を提示し、合意を形成すること。明確な『承認（開始の許可）』を得るまでは、コード変更・ファイル書き込み・コマンド実行を含む実作業を絶対に開始してはならない。**

AIがいきなりファイルを書き換えることを禁止し、まず「実施計画書（`implementation_plan.md`）」を作成させて人間に提示させます。
人間が「承認」を出して初めて実装に入る。このワンクッションがあるだけで、要件のズレや無駄なファイル生成はほぼゼロになりました。

### 2. マイクロコミットの徹底（第3条）
> **「関数1つ修正」「エラー1件解消」など、動作確認できた極小ステップごとに必ず `git commit` を実行すること。**

AIに任せると、10個のファイルを一気に修正して「全部直しました！」と報告しがちです。これでは後から特定の修正だけを切り戻す（revertする）ことができません。
「テストが通る最小単位」で小まめにコミットを残させることで、Gitの履歴が人間以上の美しさで整理されます。

### 3. テスト駆動と自律検証（第2条）
> **対象ファイルを最小限かつ正確に編集すること。編集後は自律的にテスト（`npm test` / `npm run build`）を行い、結果を確認すること。**

コードを書いた後、AI自身にテストスイートを実行させます。テストが1件でも落ちていれば、「修正完了」と嘘をつくことは許されず、パスするまで自身で原因を分析・再修正します。

### 4. 誇大表現・過剰修飾の禁止（第4条）
> **「究極の」「完璧な」「一瞬で」などの劇的な脚色は一切排除すること。報告・回答は常に客観的、簡潔、かつ技術的な事実のみを伝えること。**

AIは時に「完璧なセキュリティ対策を施しました！」「究極のパフォーマンスを実現しました」と大言壮語しがちです。
ルールでこうした脚色を禁止し、客観的な事実（「3箇所の脆弱性を修正、テスト15件全通過」など）だけを報告させることで、人間側も冷静にコードレビューに集中できます。

## 人間とAIの新しい役割分担

この開発を通じて見えてきた、AI時代におけるエンジニアの立ち位置です。

| 役割 | 人間が担当すること | AIアシスタントが担当すること |
| :--- | :--- | :--- |
| **企画・要件** | 「誰のどんな課題を解くか」の意志決定 | 類似事例やプラグイン構成のブレインストーミング |
| **設計・計画** | 計画書のレビューとGO/NO-GO判断 | 詳細なファイル構成案・実施計画の作成 |
| **実装** | アーキテクチャの方針指示 | TypeScriptコードの生成、DOM操作、CSS構築 |
| **品質保証** | セキュリティの観点出し・受入テスト | 自動テスト実行、型チェック、ビルド確認 |
| **ドキュメント** | 読者目線での推敲・発信 | 仕様書、README、解説記事の下書き作成 |

人間は「タイピング」から解放され、**「アーキテクチャの意思決定」と「安全性のレビュー」**に全リソースを投入できるようになります。

## おわりに

「AI開発初心者ナビ」は、AIを使って開発を始めたい人のためのナビゲーションツールですが、その開発プロセス自体が**「AIと人間が協調して規律あるソフトウェア開発を行うための実践」**でもありました。

もしこれからAIエージェントを活用した開発に挑戦される方は、ぜひプロンプトのテクニックだけでなく、**「AIにどんな規範（ルール）を守らせるか」**というガバナンスの視点を持ってみてください。

AIは適切なガードレールを与えることで、最高の開発パートナーへと進化します。
